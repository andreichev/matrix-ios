# Оболочка и уведомления

Реализовано 26.09.2026. Сборки и тесты не запускались; сервер и БД не изменялись агентом.

## Поставка

1. Обновить backend: V73 добавляет флаг push у сессии и таблицу обычных APNs-подписок.
2. Обновить matrix-mobile и matrix-frontend: мост авторизации/звонков нужен мобильной оболочке, состояние устройств и участники звонка обновлены в обоих интерфейсах.
3. Установить новую iOS-сборку. Используются существующие APNS_* и capability Push Notifications. Для обычных уведомлений появится отдельный системный запрос разрешения; дополнительных сертификатов, Firebase и серверных портов нет.

Выбранный в iOS сервер должен обслуживать `/matrix-mobile/` и `/api/v1/` на одном origin. Локально можно использовать Vite с base `/matrix-mobile/` и API/WebSocket proxy к backend; указать в приложении origin Vite, а не standalone backend. HTTP допустим только для localhost в Debug/симуляторе. На телефоне требуется доступный HTTPS-origin.

## Границы

- `WorkspaceController` и `WorkspaceView` содержат WKWebView. `MatrixWebBridge` разрешает только token/logout/openCall/notificationSettings от main frame на выбранном origin и пути `/matrix-mobile/`. Проверки TLS не отключены; внешние ссылки открываются вне привилегированного WebView.
- `AuthService` единолично обновляет refresh-токен, хранит его в Keychain. В web передаются access-токен и срок действия, только в память. WKWebView использует отдельное непостоянное хранилище. После выхода создаётся новый web-контекст без данных предыдущего пользователя.
- `NativeCallCoordinator` по-прежнему владеет звонком независимо от WebView. Нативный клиент не запускает BrowserCallSession и не показывает второй web-баннер входящего. Web-клиенты вне оболочки работают как раньше.
- При сворачивании оболочки web-соединение закрывается, нативный активный звонок продолжает работать. Общая прежняя политика сохранена: обычные push подавляются, когда сервер считает пользователя активным по WebSocket, в том числе на другом устройстве. Прямые VoIP-приглашения обрабатываются отдельно.
- Обычные APNs используют тот же ключ и HTTP/2-клиент, но другой token/topic (`bundle-id`, без `.voip`). Входящие не дублируются обычными баннерами. Ошибки доставки не откатывают событие. Получатели загружаются одним запросом на пакет, доставка вынесена в ограниченную очередь.
- Уведомление содержит UUID сессии; переход разрешён только для неё и только внутрь приложения. При открытии приложения доставленные уведомления очищаются. Сервер не хранит push для отложенной доставки через APNs (`expiration=0`); доставка офлайн не гарантируется.
- `WebDocumentService` обрабатывает скачивание авторизованных blob-документов и открывает Quick Look с возможностью поделиться/сохранить. Временные файлы удаляются после закрытия просмотра или выхода. Дополнительной передачи токенов в URL скачивания нет.

## Устройства

- API списка сессий возвращает `push`: enabled/web/ios/voip/iosPermission. Секретные токены не возвращаются. Два фиксированных запроса: сессии и состояния всех их подписок, без отдельного запроса на каждую строку.
- `PUT /api/v1/auth/sessions/{id}/push` с `{ "enabled": false }` разрешён только владельцу действующей сессии. Флаг сохраняется отдельно от регистрации; повторная регистрация подписки не включает его обратно.
- Переключатель отключает и обычные уведомления, и входящие звонки на выбранной сессии, но не завершает авторизацию и не скрывает события внутри приложения. Другие устройства не меняются. Уже отправленный push невозможно отозвать.
- «Привязка» означает наличие регистрации, а не гарантию доставки. Учитываются также общие настройки сотрудника и системное разрешение iOS/браузера. На текущем iPhone из «Устройств» и профиля можно открыть системные настройки уведомлений.
- Выход/отзыв сессии удаляет обычные и VoIP-регистрации; просроченные сессии не участвуют в доставке. APNs удаляет недействительный токен без удаления более свежей регистрации.

## Ручная проверка перед TestFlight

1. Вход, повторное открытие приложения, истечение access-токена, выход и вход другим сотрудником. Web и звонки должны использовать одну сессию.
2. Из чата открыть звонок: один системный вызов, статус ожидания, имя собеседника. Для трёх приглашённых — название чата, даже если ответили только двое.
3. Входящий на заблокированном экране, ответ, отказ, завершение, возврат к web-интерфейсу. Звук при блокировке/смене сети/Bluetooth.
4. Свернуть приложение без активного звонка и закрыть другие активные клиенты пользователя. Отправить сообщение/комментарий/согласование: проверить обычное уведомление и переход к соответствующему экрану, включая холодный запуск.
5. Отключить push конкретного iPhone через другой клиент. Перезапустить приложение: запрет должен сохраниться, остальные устройства продолжают получать уведомления. Включить обратно. Повторить для браузерной подписки.
6. Запретить обычные уведомления в настройках iOS: в «Устройствах» виден запрет. Вернуть разрешение, открыть приложение; проверить обновление состояния.
7. PDF, изображения, XLSX, загрузка вложений, «Скачать», открытие внешней ссылки, клавиатура и нижняя safe area. Закрытый web-раздел не должен получать нативный access-токен.
8. Иконка, описание приложения, тестовая учётная запись и проверка Release/production APNs перед ручной загрузкой TestFlight. История звонков и Share Extension — следующие отдельные этапы.

Документация Apple: [мост с ответом JavaScript](https://developer.apple.com/documentation/webkit/wkscriptmessagehandlerwithreply), [разрешение обычных уведомлений](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications).
