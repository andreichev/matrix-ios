# Архитектура Matrix iOS

Следуем разделению UIKit-кода MoveAndPray, без копирования его предметной логики и без React Native.

## Экран

Поток: `View -> Controller -> Interactor -> Controller -> View`.

- `FeatureView: UIView` создаёт subviews, стили и constraints. Отображает состояние, сообщает намерения пользователя через weak delegate или callback. Не обращается к сервисам и не выполняет навигацию.
- `FeatureController: UIViewController` владеет отдельной корневой View, устанавливает её в `loadView()`, управляет lifecycle, связями и presentation. Не собирает layout и не выполняет сетевую работу.
- `FeatureInteractor` появляется только при наличии прикладного сценария. Координирует сервисы, асинхронные операции и отмену; возвращает результат через weak output/delegate. Не знает View и не показывает UI.
- `DisplayModel`, состояния, DataSource и другие роли добавляются по необходимости, не для заполнения шаблона.

Каждый экран находится в собственной папке `Controllers/<Screen>/` вместе с View и Interactor. Subviews инициализируются через `private lazy var ... = { ... }()`. Методы View: `setupStyle`, `addSubviews` (только иерархия), `makeConstraints` (только constraints). Отдельный Presenter, глобальный ViewModel, DI-контейнер и универсальные базовые контроллеры сейчас не нужны.

## Общий код

- `MainFiles`: системные точки входа и сборка зависимостей. `SceneDelegate` создаёт окно и корневой экран.
- `Services`: сеть, хранение сессии, системные уведомления и звонки. Зависимости передаются явно через init; протоколы вводятся для реальной замены/тестирования.
- `Helpers`: небольшие утилиты без предметного состояния; здесь не хранятся сессии и звонки.
- `Resources`: конфигурация, изображения и локализации. Секреты и серверные ключи сюда не попадают.

UI меняется на MainActor. Длительная работа не должна блокировать главный поток. Delegate/output ссылки слабые; задачи, подписки и таймеры имеют владельца и симметричное завершение. Не выполнять работу в deinit через ленивую зависимость, которая ещё не создана.

## Границы будущей интеграции

- Обычная работа в Матрице остаётся в `matrix-mobile` внутри WKWebView. Нативно добавляются функции устройства, прежде всего звонки и push.
- Для звонка используется текущий серверный протокол и SFU/TURN. Нативное медиа и сигнализация не зависят от работающего JavaScript/WebView.
- Одно действие открывает либо web-звонок, либо нативный звонок, но не оба одновременно.
- Нативный звонок имеет собственный жизненный цикл с CallKit. Блокировка/фон не равны выходу; явный выход завершает подключение. Системное сворачивание интерфейса не должно случайно завершать звонок.
- Авторизация имеет одного владельца обновления токенов; refresh-токен хранится в Keychain. Выход и отзыв сессии согласованно завершают web, нативные подключения и подписки устройства.
- Мост WebView принимает только конкретные команды от доверенного origin/main frame; внешние сайты не получают токены или доступ к нативным функциям.
- До основной интеграции проверить нативный медиаклиент на реальном iPhone: групповой звук с web, TURN, фон, блокировку, смену сети и аудиомаршрутов.

Нативный клиент звонков и авторизация реализованы. CallSocket использует прежний endpoint; для PushKit backend дополнен регистрацией устройства, отправкой APNs и отклонением приглашения до подключения WebSocket. MediaWorker держит C++/WebRTC-объекты на последовательной очереди; SfuAudioSession координирует их с сигнализацией на MainActor. CallInteractor владеет подключением и отбрасывает результаты старых попыток по generation/sessionId.

AppDelegate владеет AppServices: AuthService, SystemCallService (один CXProvider), VoipPushService и NativeCallCoordinator. NativeCallCoordinator удерживает активный CallInteractor независимо от UI. AppCoordinator отвечает только за навигацию. Входящий может запустить звонок без Scene/Controller; экран подключается к тому же Interactor, не создавая второе соединение. Выход назад остаётся явным завершением, сворачивание приложения — нет.

SystemCallService слабо ссылается на Interactor. Системный UUID сохраняется при переподключении; для входящего совпадает с UUID серверного звонка, для исходящего создаётся локально. На устройстве CallKit активирует аудио; MediaWorker не вызывает setActive. В симуляторе остаётся самостоятельное управление аудио. Системные действия и кнопки используют один обработчик mute; завершение освобождает медиа и сигнализацию.

Удержание и системная история/повторный набор отключены. Следующий этап после проверки входящих на iPhone: WebView и мост авторизации. Firebase, расширения и гостевой доступ пока не добавляем. Настройка и ограничения PushKit описаны в [ios-push.md](ios-push.md).
