# Matrix iOS

UIKit-оболочка над matrix-mobile с нативными аудиозвонками и APNs-уведомлениями. CI нет, сборки распространяются вручную через Xcode. Интеграция оболочки требует ручной проверки на iPhone.

## Возможности

- Вход на указанный сервер, Keychain, единое обновление токенов и выход с отзывом серверной сессии.
- После входа открывается matrix-mobile. Авторизацией управляет нативная часть; JavaScript получает только access-токен в память. Звонки из чата открываются нативно, без параллельного web-звонка.
- Обычные уведомления открывают связанный экран. В «Организация → Устройства» видны привязки push и переключатель уведомлений/входящих звонков для каждой сессии.
- Доступные чаты и текущие звонки. Нужны членство в чате и разрешение звонков от администратора.
- Явное присоединение, постраничная галерея подключений, микрофон и выход.
- Приглашённые участники отображаются со статусом ожидания/отказа/пропущенного звонка. Для двух человек название — имя собеседника, для группы — название чата; устройства одного человека не меняют название.
- Кнопка громкой связи. По умолчанию используется разговорный динамик или выбранная системой гарнитура; кнопка отражает фактический маршрут, в том числе после смены маршрута через CallKit.
- Нативные mediasoup/WebRTC, существующий WebSocket-протокол, SFU/TURN. Токен в Authorization, не в URL. Прямого доступа к API SFU нет.
- Переподключение сигнализации, ICE restart, обновление участников. При выходе микрофон выключается сразу, при восстановлении сохраняется mute.
- AVAudioSession для разговора и Bluetooth HFP, режим background audio. Фоновые сценарии ещё требуют проверки на физическом iPhone.
- CallKit на iPhone: регистрация исходящего звонка/присоединения, системные mute и завершение. Аудио активирует система; WebRTC получает callbacks активации/деактивации. При переподключении сохраняется тот же системный звонок.
- Входящие через PushKit/APNs и CallKit, включая запуск без открытого экрана. Ответ, отклонение, завершение по сигнализации и сроку приглашения. Нужна [настройка APNs](context/ios-push.md).

Для CallKit в Info.plist включены Background Modes `audio` и `voip`. После изменения этих настроек нужно пересобрать и установить приложение на устройство. Ошибки системных запросов выводятся в лог категории `CallKit` (операция, домен и код, без данных звонка).

**Не реализованы:** история звонков и Share Extension. Подготовка распространения через TestFlight/App Store остаётся ручной.

В симуляторе CallKit намеренно обходится, используется прежний режим аудио. Его работоспособность не подтверждает системное поведение на iPhone. Удержание/объединение независимых звонков и повторный набор из системной истории пока отключены. При принятии другого телефонного вызова не обещаем сохранение конференции на удержании.

## Запуск

Открыть `Matrix Workspace.xcodeproj`, схема `Matrix Workspace`. Для iPhone проверить Team в Signing & Capabilities и включить Developer Mode, если Xcode попросит.

Bundle ID `com.andreichev.matrix`, автоматическая подпись. Минимальная iOS приложения **17.6**; настройки Team сохранены.

1. Backend и SFU запускает разработчик. Нужны backend с миграцией V73, обновлённый matrix-mobile и прежние настройки APNs. Новых ключей не требуется. Без APNs остаётся ручное присоединение.
2. На выбранном origin должны быть доступны `/matrix-mobile/` и `/api/v1/`. Один backend на `localhost:8080` больше не обеспечивает загрузку оболочки: для локальной работы нужен web-сервер с проксированием API. HTTP разрешён только для loopback в Debug. Для удалённых серверов и Release нужен HTTPS с доверенным сертификатом; проверка TLS не отключается.
3. На физическом iPhone localhost означает телефон. Нужен доступный ему HTTPS-сервер; SFU должен объявлять доступный телефону IP, а медиапорты и TURN должны быть доступны.
4. Войти сотрудником, выбрать чат и нажать «Присоединиться». На втором устройстве открыть тот же звонок в web. Не тестировать на рабочих чатах без согласования: start отправляет их участникам настоящие приглашения.
5. Назад и выход с экрана завершают подключение. Сворачивание приложения само по себе не вызывает выход.

До входа сетевых запросов нет. Адрес сервера вводится пользователем, пароль не сохраняется. При недоступном сервере локальный выход не подтверждает отзыв серверной сессии: при необходимости завершить её через «Устройства» другого клиента.

```sh
xcodebuild \
  -project 'Matrix Workspace.xcodeproj' \
  -scheme 'Matrix Workspace' \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO \
  build
```

## Структура

```text
Matrix Workspace/
  MainFiles/                 AppDelegate, SceneDelegate, AppCoordinator, AppServices
  Controllers/
    Login/                   Controller, View, Interactor
    CallsList/               Controller, View, Interactor
    Call/                    Controller, View, Interactor, ParticipantCell
  Services/
    Auth/                    AuthService, KeychainStore
    Network/                 HTTPClient, ServerAddress
    Calls/                   Сигнализация, медиа, CallKit, PushKit, NativeCallCoordinator
  Helpers/                   JSONValue
  Resources/                 Info.plist, Assets, LaunchScreen
Tests/                       XCTest
test-support/                Локальная SFU/Chromium-проверка
```

View создаются кодом: lazy closure-based subviews, `setupStyle`, `addSubviews` только для иерархии, `makeConstraints` только для constraints. Блокирующие операции C++ вынесены на отдельную последовательную очередь; UI и координация явно помечены MainActor.

Зависимость: [Mediasoup-Client-Swift](https://github.com/VLprojects/mediasoup-client-swift), строго `0.13.2`, зафиксирована в Package.resolved. Xcode загружает бинарные Mediasoup/WebRTC XCFramework. Это сторонняя обёртка. Перед выпуском проверить актуальность библиотеки, лицензии/Privacy Manifest и требования App Store. Прототип пока на русском; иконка не заполнена.

## Тесты

Cmd+U: протокол, Keychain/ротация токенов и загрузка нативного Opus. Для тестов Keychain нужна обычная подпись симулятора: не задавать `CODE_SIGNING_ALLOWED=NO`.

Интеграционный тест запускается отдельно с собственным SFU и Chromium с синтетическим звуком. Нужны соседние matrix-sfu и matrix-mobile, установленные зависимости matrix-sfu и его Chromium. Основной backend и рабочая БД не используются:

```sh
../matrix-sfu/node_modules/.bin/tsx test-support/native-sfu.mts
```

В другом терминале:

```sh
xcodebuild -project 'Matrix Workspace.xcodeproj' \
  -scheme 'Matrix Workspace' \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  MATRIX_SFU_TEST_URL=http://127.0.0.1:38761 test
```

Без переменной интеграционный тест пропускается. После проверки остановить fixture через Ctrl+C; перед новым прогоном перезапустить. Fixture слушает только loopback. Проверка RTP в симуляторе не заменяет проверку слышимости, AirPods, телефонных прерываний, блокировки и смены сети на iPhone.

## Проверка CallKit на iPhone

Обновление CallKit от 26.09.2026 не собиралось и не прогонялось агентом. Проверять на устройстве с доступным HTTPS-backend и SFU; не использовать рабочие чаты без согласования.

1. Позвонить из приложения и присоединиться из web: звук должен идти в обе стороны, системный интерфейс должен показывать название чата.
2. Выключить/включить микрофон в приложении и системном интерфейсе: состояние должно совпадать, удалённый участник не должен слышать звук при mute.
3. Завершить звонок системной кнопкой, затем отдельно кнопкой приложения и возвратом назад: исчезают системный звонок, микрофон и подключение в web. После завершения с заблокированного экрана разблокировать iPhone: приложение должно показывать список звонков, а не завершённый звонок. Повторный звонок должен запускаться.
4. Заблокировать экран, свернуть/вернуть приложение: текущий звонок не завершается от одного перехода в фон. Проверить включение/выключение громкой связи, возвращение к разговорному динамику без гарнитуры, подключение/отключение AirPods и смену аудиомаршрута через CallKit. Подсветка кнопки громкой связи должна соответствовать реальному выводу звука.
5. Во время звонка принять обычный телефонный вызов. Убедиться, что Матрица освобождает аудио и не продолжает захват микрофона. Удержание не поддерживается, система может предложить завершить звонок Матрицы.
6. Переключить Wi-Fi/мобильную сеть: проверить восстановление звука, отсутствие второго системного звонка и сохранение mute.
7. Отказать в доступе к микрофону, отключить сеть при подключении, отозвать доступ к звонкам: не должно оставаться зависшего системного звонка.

Проверка входящих и пробуждения приложения: [ios-push.md](context/ios-push.md). Новая реализация пока не проверена на устройстве.
